Fix the video encode that libx264 kept rejecting, and hand those files back

Reported from the admin Media tab: a clip listed twice, once "KEPT - encode
failed" and once "FAILED", right after the upload-pipeline change. It is not
that change -- the same failure is in the log from the day before -- and it is
not the sandbox either: the file is served untouched, which is the designed
fallback. But it is a real bug, and it had been silently preventing whole classes
of video from ever being compressed.

Reproduced against the stored object in the container, with the full stderr the
app truncates away:

    [libx264] width not divisible by 2 (1071x1080)
    [libx264] Task finished with error code: -22 (Invalid argument)

The clip is 720x726 portrait. SCALE_VID was `scale=1920:1080:
force_original_aspect_ratio=decrease`, which does two wrong things:

- it UPSCALES anything smaller than the box (a 726p phone clip re-encoded to
  1080p -- needless CPU, a bigger result, and then the 8% rule throws it away),
  where the still pipeline has always capped at the source (`min(2048,iw)`);
- it lands on ODD dimensions whenever the fitted aspect ratio says so, and
  libx264 with yuv420p refuses those outright. 720x726 fitted to 1080 tall is
  1071 wide, so the encode died and the ledger recorded a terminal
  `kept/encode_failed` -- meaning the file would never be attempted again.

Both are fixed in one expression: the box is capped at the source size, and a
second stage rounds the fitted result to even dimensions (it can only shave one
pixel, which is invisible). Verified on the same 720x726 clip: the old filter
fails with exactly production's error, the new one exits 0 at 720x726.

- oncePolicy('even-dim-video') hands back the video keys already sitting in the
  ledger as `kept/encode_failed`, or the fix would never reach them.
- One encode failure now logs ONE row. It logged the encoder's error AND a
  `kept` row for the same attempt, which is why one file read as two.
- The admin feed prints the reason on a FAILED row too (the first line, capped);
  a bare FAILED badge with nothing after it is a dead end.
- scripts/test-compress-types.js pins both properties of the filter and encodes a
  720x726 portrait clip for real, asserting it succeeds at even dimensions and
  is never upscaled.
